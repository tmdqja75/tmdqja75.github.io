# How LLM Agents Operate and Call Tools

One of the most exciting concepts that has recently emerged in the field of natural language processing is the **LLM Agent (Large Language Model Agent)**. This advanced system has evolved from merely generating text to actively calling external tools and continuing to reason based on execution results.

In this blog post, we will explore:
- What an LLM Agent is,
- How Tool Calling operates.

## What is an LLM Agent?
An LLM Agent is, quite literally, “an agent that performs tasks by leveraging external tools.” While LLMs like GPT and Claude possess strong natural language processing capabilities, they cannot directly carry out tasks such as calculations, searches, or API calls.

Therefore, an LLM Agent comprises the following components:
- LLM: Determines when to use which tool and the arguments to call it with.
- Tool List: A collection of external functionalities that the model can call.
- Orchestrator: Executes the tools requested by the model and relays the results back to the model.

## Orchestrator / Framework
- The medium that facilitates requests and results between the LLM and the tools is referred to as the orchestrator or framework.

LangChain is a prominent LLM framework. It reads tool call information generated by the LLM, executes the actual tools, and then feeds the results back to the model.

The roles of LangChain include:
1. Defining and registering tools (e.g., using @tool).
2. Passing the tool list and schemas to the model.
3. Executing the tool calls when requested by the model.
4. Receiving results and returning them to the model to facilitate further reasoning.

In other words, LangChain acts as the link that enables the seamless operation of LLM Agents.

## LLM and Tools

So, how does the LLM know which tools to use and when? Let's delve into the process step-by-step.

### System Prompt

In an LLM Agent, the System Prompt is a fixed message that establishes the overall behavior of the model in interaction with the LLM. It is typically structured in the following format:

```
"You are an intelligent AI assistant capable of utilizing various external tools.  
Based on user queries, you should select and call the most appropriate tool from the list provided below.

## Tool List:
  {
    "name": "SearchWeb",
    "description": "Searches for information on the web.",
    "parameters": {
      "type": "object",
      "properties": {
        "query": {"type": "string", "description": "Keyword to search for"}
      },
      "required": ["query"]
    }
  },
  {
    "name": "Calculator",
    "description": "Performs simple math calculations.",
    "parameters": {
      "type": "object",
      "properties": {
        "expr": {"type": "string", "description": "Math expression, e.g., '12 * 8 + 3'"}
      },
      "required": ["expr"]
    }
  }
```

### Tool Calling Method:
• Specify only one action tool call in JSON format under the “Action:” field.  
• The JSON object must adhere to the following format:
```json
{
  "action": "<tool name>",
  "action_input": { /* Parameters to be passed to the tool */ }
}
```

The method of informing the LLM about the types of tools and their usage is by embedding descriptions of the tools as strings in the System Prompt. To ensure the LLM comprehends the tools effectively, the tool descriptions must include at least the following elements:
- Tool name
- Tool description
- Tool input variables and their data types
- Required input variables for the tool

### User Input Handling

When a user inputs a system prompt along with their question, the LLM references the tool list in the System Prompt and returns the tool usage in a JSON response formatted in natural language (string). For example, if a user asks the Agent, `What new model has been released by OpenAI today?`, the LLM may respond with something like this:

```json
[{
    "type": "function_call",
    "action": "SearchWeb",
    "action_input": "{\"query\":\"OpenAI latest model\"}"
}]
```

### Framework Processing
- The LLM framework (e.g., LangChain) receives the LLM's response, calls the tool (function) requested by the LLM, and inserts the function input variables generated by the LLM to produce the tool's output. The result generated by the tool is then entered back into the LLM's System Prompt along with the user query, leading to the final answer. The following diagram illustrates the flow of this process.
